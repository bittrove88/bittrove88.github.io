# ARCLINE コンポーネント美術の実装引き継ぎ

本資料は、承認済みv0.3を基準に地形・オブジェクトの制作を続ける担当者と、将来ゲームへ組み込む担当者向けの引き継ぎ。今回のPRは美術資料・編集データ・独立プレビューを追加し、ゲームの描画やプレイルールを変更しない。

## 担当と正本

| 担当 | 正本と責務 |
| --- | --- |
| 背景制作 | [PR #100](https://github.com/bittrove88/bittrove88.github.io/pull/100)の入江背景、[PR #75](https://github.com/bittrove88/bittrove88.github.io/pull/75)の背景資料。背景の構図・配色・承認状態を管理 |
| コンポーネント制作 | 本ディレクトリ。テーマ材質、共通機能部品、形・色面・状態の見本を管理 |
| マップ設計 | 現行のステージ正本と個別設計資料。形状・配置・破壊単位・攻略課題を管理 |
| ゲーム実装 | `game/README.md`と`game/runtime.json`に従い、承認された描画を接続し動作を検証 |

`references/` のSVGは比較用スナップショットで、背景の編集正本ではない。`sources.json` の固定コミットとGit blob・SHA-256を保持する。背景を更新する場合は担当側の新しい正本と承認状態を確認し、参照元台帳と比較見本を一緒に更新する。PR #75に含まれるゲーム組み込み試作を、この資料の依存として取り込まない。

`map-geometry.json` はmainの `3ebb4c9` における現行4面・61面の比較用形状。未実装の新マップ案へ置き換えたり、ゲームのステージ正本として読み込ませたりしない。単位や出典は `sources.json` に記録している。

新しい見本を作る際は、テーマ・対象面・素材の説明・通常材質パレット・共通部品の使用箇所・状態・出典・確認結果を揃える。造形を変更した場合は、以前の見本の検証結果を新しい見本の結果として引き継がない。

## ゲームへ接続するときの契約

- **描画専用**：座標、当たり判定、足場、破壊単位、歩行140px、70度の接地条件、物理、AI、在庫、セーブを維持する。
- **座標系**：地形と装置は現在のワールド変換に追従。PR #100の背景は画面座標で固定する契約のまま扱う。装飾をカメラのフレーミングや衝突形状の入力にしない。
- **接地と破壊**：現在有効なポリゴン・支持面・支点を参照する。破壊した穴、開いた橋、消えた支持面に塗りや接地縁を残さない。反射面の見た目を実際に反射する辺へ合わせる。
- **状態表示**：物理が使う実際の現在値と切り替え予約を参照する。表示のための独立した状態進行や新しいゲーム効果を作らない。
- **射線**：Easy全軌道、Normal累積距離半分、Hard方向のみを維持。装飾・状態表示のために隠れた着弾先や衝突結果を追加表示しない。
- **表示寸法**：通常倍率と90%チャージ縮小、見渡し、DPR・画面回転でも輪郭と記号が読めるようにする。内部の細部を省略しても機能記号を失わない。
- **描画状態と負荷**：Canvasのtransform・clip・alpha・line dash等を復元。美術のばらつきに戦闘RNGを使わず、静止形状のキャッシュや画面外省略で負荷を抑える。
- **配布**：正式な編集元、依存順、生成、キャッシュを `game/runtime.json` に合わせる。本資料のPythonや比較用スナップショットをゲームの本番描画へそのまま読み込ませない。

## 実装時の確認

568×240、844×390、回転端末で、実際の自機・敵・実弾・照準ガイド・HUDと合成する。通常表示、90%チャージ縮小、見渡し、斜面、破壊前後、橋の姿勢、領域の状態変更を含める。

- 同じ入力での弾道・衝突・着地・破壊・敵行動・保存結果が、美術の適用前後で一致する。
- 入江の船着場や岬、火山の地層と、実際の足場・壁・作用範囲を混同しない。
- 通常の岩と破壊材、反射面と水面、背景の煙と作用領域を識別できる。
- 色の違いに加え、形・亀裂・反射辺・記号から機能を読み取れる。
- 既存の `npm test`、`npm run check:generated`、対象ブラウザテストを実施し、実機確認と分けて報告する。

独立プレビューの合格は実ゲームでの視認性やプレイの合格を意味しない。実装依頼を受けた範囲でゲーム統合PRを作成し、美術制作・実装・検証・公開の状態を分けて記録する。
