# 鏡の岸壁 — 後工程への引き継ぎ

## 状態と対象

**背景デザイン承認済み（2026-11-07）。ゲーム実装は未着手。** 正本の `approved` は `true`。今回のユーザー承認を記録。

- 対象：6〜10面の5面共通、`themeIndex=1`。
- 基準寸法：1120×604。中央寄せのcoverを標準とし、containは資料確認用。
- 編集正本：[mirror_cliffs.json](mirror_cliffs.json)。描画専用のデータとして扱う。
- 描画API：`ArcMirrorCliffsBackground.validate(scene)`、`appliesToStage(stage)`、`draw(ctx, widthCssPx, heightCssPx, scene, {fit:'cover'})`。
- 面番号は1始まりの整数。ゲーム側のテーマ番号と併せて照合し、6未満・11以降・100面には適用しない。

## 描画・連携

1. 背景を画面座標で最初に描画し、実地形・機体・弾道・ギミック・UIを後から重ねる。
2. 岸壁、岩柱、アーチ、水面、映り込みには当たり判定・選択判定を設けない。背景は水切り・反射の判定資料ではない。
3. 背景をカメラの平行移動やズーム、照準、自機の移動、着弾に連動させない。各面で同一の風景を使用する。
4. 既存の背景グラデーションや汎用ランドマークは対象の6〜10面で二重描画しない。他テーマと専用背景を保持する。
5. CSSピクセルの寸法を渡し、既存DPR変換を保全する。描画モジュールはsave/restoreでCanvasの状態を戻す。描画中は不透明度1・source-over・影とフィルターなしを設定する。
6. 正本 `game/runtime.json` と既存生成手順に従い、正式な本番統合は別PRで行う。このフォルダの独立プレビューをゲームから直接ロードしない。

## 統合時の受入れ条件

- 6・7・8・9・10面で同一背景、5面・11面・100面では既存背景を維持する。
- 1120×604／844×390／568×240でゲームの自機・敵・地形・ガイド・実弾・HUDを重ねて確認する。393×852は横向きゲームの回転確認として別途扱う。
- 6面と10面を含め、Easy全軌道・Normal半分・Hard方向のみの射線表示を確認する。
- 水面を実際の反射材と誤認しないか、アーチを通行口や射線の案内と誤認しないかを確認する。
- マップ見渡し、ズーム、射撃・着弾、機体移動、ポーズ復帰により背景がゲーム操作や表示を妨げない。
- 衝突・弾道・AI・難易度・進行・セーブを維持し、視認性調整は背景側で行う。
- `npm test`、`npm run check:generated`、対象のブラウザ検証を行い、実ゲームのスクリーンショットを残す。実機と公開URLは独立した確認として記録する。

今回の単体検証は [VALIDATION.md](VALIDATION.md) を参照。実ゲーム上の視認性・実機・公開は未検証。
