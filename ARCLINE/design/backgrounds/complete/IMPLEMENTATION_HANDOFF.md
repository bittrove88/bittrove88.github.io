# 全背景コレクション — 実装引継ぎ

## 現状と正本

美術データと独立プレビューを制作済み。**ゲームへは未統合。** 新作29景はデザイン確認待ち。機械可読の一覧は `manifest.json`、描画データは `data/*.json`。新作の編集元は `recipes.py`、継承元は `sources/*.json`。

## 適用の優先順位

1. **100面**：現在の `ArcFinalTeam.mapIndex(state)` に対応する `final-100-0`〜`final-100-3`。mapIndexは0始まり。未指定時は通常背景へフォールバックさせず、適用エラーとして扱う。
2. **10〜90面の10刻み**：`boss-010`〜`boss-090`。
3. **その他の面**：`normal-00`〜`normal-19`。テーマ番号は `Math.floor((stage-1)/5)`。

`ArcBackgroundCollection.select(scenes, stage, mapIndex)` はこの優先順位の参照実装。面番号は1始まりの整数。中ボス5・15…95面は通常テーマの背景を使う。

通常テーマの `stageRange` は分類と共通背景の候補範囲であり、大ボス専用の優先判定を上書きしない。旧データにある「5面同じ」という記述は、ユーザーの今回の大ボス別背景依頼によってこの範囲だけ更新される。

## 描画

```js
const background = ArcBackgroundCollection.select(scenes, stageNumber, finalMapIndex);
ArcBackgroundCollection.draw(ctx, widthCssPx, heightCssPx, background, {fit:'cover'});
```

- 各景の基準寸法は `size` を使う。大半は1120×604、継承した火山は1000×540。
- 画面座標で中央寄せcover。照準やカメラ移動・ズーム・機体位置・着弾・ターンと連動させない。
- 背景を最初に描き、実地形・屋根・障害物・全ギミック・自機・敵・照準・ガイド・実弾・エフェクト・HUDを後から描く。
- 背景に当たり判定、選択判定、反射判定、操作表示を与えない。色面の水・結晶・橋・アーチ・照合口は装飾。
- 既存グラデーション、汎用山並み、ランドマークと重複描画しない。旧最終戦背景の置換は4景すべて揃えて行う。
- CSSピクセルの幅・高さを渡し、既存DPR変換を保全する。描画モジュールはsave/restoreで状態を復元する。
- `index.html`、PNG、SVGは確認用。ゲームは描画用JSONと必要なモジュールを正式な生成手順で取り込む。

## 最終戦の移動

移動時だけ `transition()` を使う案。進行度は既存の `travel.age/travel.duration` から得る。旧背景は55%未満、新背景は55%以上。通常2.2秒／動作軽減0.7秒を維持し、ゲームへ別時計を追加しない。

扉の描画は後工程で既存崩壊・画面切替との重なりを確認する。戦闘中の背景は静止。移動演出に合わせた新しい操作制限や物理処理は追加しない。詳細は [ARCHEART.md](ARCHEART.md)。

## 統合時の受入れ

- 全1〜99面と100面のmapIndex0〜3の計103条件で選択を検証する。図形・色・データを戦闘パラメーターへ流用しない。
- ボス直前9・19…89面と大ボス10・20…90面を対で比較し、テーマ継承と別背景の切替を確認する。
- 96〜99面に最終4景の背景名・帰還の意味を前倒し表示しない。100面の4景は固定担当順と一致させる。
- 1120×604／844×390／568×240で実ゲームの地形、自機、敵、全ガイド、実弾、ギミック、HUDを重ねて確認する。393×852は回転対応の確認として別に扱う。
- 少なくとも各大ボス・最終4戦場でEasy全軌道／Normal半分／Hard方向のみのガイドが読めるか確認する。
- 雲C、反射面、結晶K、磁場・極性端子など機能色と背景の混同を確認する。問題は背景側の彩度・明度・形・位置で修正する。
- マップ見渡し、移動、射撃・着弾、転移、ポーズ復帰、最終戦の移動と敗北機からの再挑戦で確認する。
- 地形、AI、HP、手数、必殺、保存、進行、公開URLを維持。`game/runtime.json` と正式ビルド・依存・キャッシュ手順へ合わせる。
- `npm test`、`npm run check:generated`、対象ブラウザ検証を実施し、実機・公開URL確認は別途記録する。

デザイン承認、ゲーム実装、単体自動検証、実戦視認性、実機、公開を別の状態として管理する。今回の132単体描画を実ゲーム検証の代用にしない。
