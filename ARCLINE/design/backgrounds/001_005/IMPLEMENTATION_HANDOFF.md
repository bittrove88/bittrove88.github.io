# ARCLINE｜1〜5面「はじまりの入江」実装引継ぎ仕様

## 0. 何が承認されたか
2026-11-07の会話で「完璧」として背景デザインを承認。**承認対象は背景の美術データ**であり、ゲーム実装や実ゲームでの視認性検証を完了した意味ではない。今後の他テーマの配色や構図の複製を意味するものでもない。

## 1. 対象・選択条件
- テーマ名：はじまりの入江。内部テーマID：`themeIndex=0`。
- 対象ステージ：1〜5の5面のみ。**全5面で単一の共通背景を使う**。面ごとの自動的な色変化、パララックスやギミックへの連動は導入しない。
- 使用API：`ArcFirstCoveBackground.validate(scene)`、`ArcFirstCoveBackground.appliesToStage(stage)`、`ArcFirstCoveBackground.draw(ctx, width, height, scene, {fit:'cover'})`。
- 正本の基準寸法：1120×604。画面への適用は中央寄せの `cover`（切り抜きを許容）を標準、`contain`は確認用。
- デザインJSONを**ゲームのランタイムデータに混入させず、描画専用アセット**として取り込む。

## 2. 配置場所・描画順
1. テーマとステージ番号の判定後、ゲームの描画Canvasで最初に背景を描画する。
2. 実際のステージ地形・屋根・障害物・破壊ブロック・ギミック領域・自機・敵・照準線・予測弾道・実弾・着弾エフェクト・UIは、背景の**後から上に**描く。
3. ゲーム側が現在描画する空の線形グラデーション、背景ランドマーク、共通の層状山並みは、対象テーマについては重ね描きしない。テーマ0以外と100面の専用背景は既存描画を保全する。
4. 本背景は画面座標ベースで固定し、カメラの平行移動・ズーム・射角・着弾・自機や敵の位置に連動しない。装飾に当たり判定や選択判定を与えない。
5. 既存CanvasのDPR変換を壊さない。CSSピクセル幅・高さを渡し、`save/restore`で状態を復元する。

## 3. 禁止・必須デザイン技法
- 背景内で**グラデーション、ブラー、エアブラシ、ノイズ、画像生成、ラスタ画像、テクスチャ、ソフトシャドウ**を使用しない。
- 空気遠近・柔らかい光・水面の階調は**不透明な単色面を隣接させたトーン差**で表現する。
- 1オブジェクトは必要に応じて正面・上面・暗面等の独立した色面で構成する。
- ユーザーが提示した参考画像をそのまま複製するのではなく、承認済みJSONの幾何学・色構成を採用する。
- 「SF」はデザイン上のテーマキーワードとして使わない。
- 背景が情報の主役にならないこと。視認性を優先し、装飾追加で視覚情報を増やしすぎない。

## 4. キャラクター／弾道の視認性
背景より常に以下を優先する。
1. 自機・敵の輪郭および被弾状態。
2. 実弾・爆発・命中箇所。
3. 照準方向と難易度ごとのガイド表示（Easy全軌道、Normal半分、Hard方向のみ）。
4. 破壊可能ブロック、反射材、移動橋、雲などのギミック状態。
5. 足場・地形の当たり判定を示す境界とHUD。

背景中の船着場・灯台・岬が**足場に見えないこと**を実ゲームで確認する。実キャラクター／弾道に背景色が重なる場合は、**ゲームルールを変えず、背景側の彩度・明度・形・配置を調整**する。特に中央の空間を弾道のための余白として維持する。

## 5. 参照・読み込みの留意点
- `first_cove.json` が編集正本で、`first_cove_canvas.js` はそれを描画する独立モジュール。`first_cove.svg`と`first_cove_preview.html`は確認用。
- プレビューHTMLは描画モジュールとJSONを埋め込んでいるため、ネットワークリクエストや外部ファイル読み込みは不要。GitHubのHTMLプレビューとローカルのファイル表示は別なので、SVGをリポジトリ内の見本とする。
- 本番統合ではランタイムの正本`ARCLINE/game/runtime.json`、生成順序、`npm run build`を遵守し、手書きの生成物のみ更新する行為は避ける。
- 既存PR #75にある21〜25面「霧の谷」の統合試作とは別案件。描画分岐に重複や読み込み順の競合を持ち込まない。

## 6. 実装担当の作業・受入れ手順
1. 元のテーマ0の保存画面と、統合後の画面を同じ端末・同じ状況で比較する。
2. 1,2,3,4,5の全ステージで同一背景が現れ、6面以降に表示されないことを確認。
3. **1120×604、844×390、568×240、393×852**の単体描画をまず確認。ゲームは横向き固定なので、393×852はビューポートの回転確認として扱う。
4. 実ゲームで自機・敵・弾道・照準ガイド・HUDを重ねたスクリーンショットを保存。少なくとも1面／5面、簡単・普通・難しいの3難易度で表示を確認する。
5. プレイヤーの移動、射撃、着弾・爆発・転移・ギミックの操作、マップ拡大／縮小、再描画、ラウンド進行、ポーズ／復帰で違和感や不具合がないか確認する。
6. 背景の適用有無でゲーム状態・衝突判定・射撃物理・AI判断・当たり判定・難易度設定・保存互換が変化しないことを検証する。
7. `npm test`、`npm run check:generated`、対象のブラウザテストを実行し、結果とスクリーンショットを実装PRに残す。確認していない項目は「未検証」と記載する。
8. プレイ可否・視認性で問題がなければ実装PRで承認し、本デザインPRは作品アートの設計正本として保持する。
