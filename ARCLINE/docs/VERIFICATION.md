# 修正単位の検証計画

2026年11月9日のユーザー指示を反映する。検証は今回の変更と、その変更が直接影響する範囲から選ぶ。過去の検査は再利用する一覧として保持する。

## 制作中の事前確認と最終合意後の本検証

制作・改善中は、仮説の確認、不具合再現、実描画、弾道・接地、入力など、判断に必要な範囲の事前確認を進める。自動化した小さな確認も利用できる。生成が実描画に必要なら行うが、全件の合否判定や配布一式の確認を慣例で開始しない。

変更内容をユーザーが最終合意してから、本検証・CIテストを開始する。実装を進める指示や未解決の指摘がある状態を、最終合意と推定しない。「この内容で検証して」「この内容でマージ」のように対象が明確な指示は、該当内容の最終合意として扱い、同じ確認を繰り返さない。

合意前の `verification-plan.json` は本検証の候補計画であり、ファイルの作成だけを実行許可と扱わない。合意前にPRを作る場合はDraftを維持する。合意済みの仕様を再検討する場合も、次のpush前にDraftへ戻す。ARCLINE checksとstaging safetyのテストジョブはDraftではスキップされ、Readyへの切替で実行する。スキップされた記録は本検証の成功ではない。手動起動は最終合意後に限る。

本検証で見つかった、合意済みの挙動を満たすための修正は同じ範囲で進める。仕様・対象が変わる場合は、その差分の合意を更新する。事前確認で成功済みの結果は条件と変更内容を照合して再利用し、本検証という名前で同じ確認を一律に繰り返さない。

## 修正前に決めること

1. 直す挙動、変更箇所、直接影響する隣接範囲。
2. 実行する検査と、それぞれで確認したいこと。
3. 今回対象外にする範囲と理由。
4. 完了条件。選択した確認が成功したら終了し、新しい変更・失敗・具体的な懸念が出た場合に範囲を更新する。

修正前の再現、修正後の同じ操作、必要な隣接動作を優先する。変更していない全キャラ・全マップ・音声・エンディングを慣例だけで追加しない。既存スイートが広すぎる場合は、必要な挙動を確認できる小さな検査へ分ける。全件確認は、具体的な広域影響やユーザーの明示依頼がある場合に選ぶ。

例として、着弾後のWorker受け渡しを直すなら、実際の発射→敵行動→次の操作を確認する。共有処理の違いがある必殺技やWorkerなしの経路は隣接範囲に含める。変更しないBGMや全100面の再攻略まで広げる理由にはしない。

## CIへ渡す計画

コード・設定を変更するPRでは、今回の修正用に [verification-plan.json](../verification-plan.json) を更新する。CIはGit差分と対象ファイルを照合し、選択したスイートだけを実行する。未記載のコード差分や古い計画の使い回し、検査名の誤指定は計画エラーとして通知する。

- `change` / `reason`：修正内容と、その検証範囲を選ぶ理由。
- `files`：今回変更するコード・設定のリポジトリ相対パス。Markdown、検証記録、計画ファイル自身は記載不要。
- `suites`：`game/tests/suites.json` にある名前を、実行するモードごとに指定する。
- `checks`：生成物一致、画面基準、配布物作成、Python依存、ネイティブ音声確認を必要に応じて指定する。
- `manual`：CIとは別に行う確認。自動検査の成功として扱わない。
- `excluded`：今回実行しない範囲と理由。

計画の十分さは変更内容と照らして判断する。CIが計画の形式を受理しただけで、未選択の挙動まで検証済みにはしない。

Markdown・検証記録だけの変更では、CIは差分の形式確認を行う。変更したリンクの確認はその修正の作業に含める。ゲームの動作検査や全生成物の再生成は自動追加しない。公開するHTML・画像・音源などの変更は、用途に応じた計画を用意する。

生成元を変えた場合に `generated`、画面の比較が必要な場合に `baseline`、配布構成を変えた場合に `package` を選ぶ。音声のデコードや再生を検査する場合は `nativeAudio: true` を選ぶ。Pythonを使う検査には `python: true` を指定する。生成・画面基準・配布物を選ぶとPython環境も用意する。

入力・ブラウザ・画面比較に同じ検査名があれば一度だけ実行する。修正単位の実行は失敗時に止まり、実行しなかった検査も記録する。修正後は失敗した対象から確認し直す。同じコード・環境で成功済みの無関係な検査を繰り返さない。

## ローカル実行

必要な名前を指定して実行する。`--list` は検査を実行せず選択結果を表示する。

    node game/tools/test.cjs browser battle-turn-continuity-browser --list
    node game/tools/test.cjs browser battle-turn-continuity-browser --skip-aac-probe --fail-fast
    npm test -- attack-motion

`--skip-aac-probe` は音声を検査しない場合に使う。音声確認を省いたことを、音声の成功として報告しない。検査名を省いた従来の `npm test` などは、指定モードの全件を実行するので、必要性を判断して使う。

Gitの比較元を指定すると、CIと同じ計画を確認・実行できる。未コミットの変更と新規ファイルも対象になる。

    node game/tools/plan-checks.cjs --base origin/main --output /tmp/arcline-check-plan.json
    node game/tools/run-check-plan.cjs /tmp/arcline-check-plan.json

## 全体検証

GitHub Actionsの `ARCLINE checks` → `Run workflow` で `full_suite` を明示して実行する。全件を選んだ理由を作業記録に残す。ローカルでも `plan-checks.cjs --full` で同じ計画を作れる。全件指定でも、重複する検査スクリプトは繰り返さない。
