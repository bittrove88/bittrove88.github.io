# ARCLINE 難易度・ステージ変更時の最小十分な検証設計ガイド

作成日: 2026-11-04  
対象: ステージ難易度、敵AI、照準誤差、武器、ダメージ、移動、学習処理などのバランス変更。  
位置付け: 将来の検証設計に再利用する指針。数値例は固定のテスト義務ではない。

## 1. 最上位原則

**変更の効果を先に最小限の新旧比較で確認し、効果が確認できたら「新版のみ」で全体の精度・バランスを検証する。**

- テスト件数を先に大きく設定しない。確認したい仮説と変更の影響範囲から必要件数を決める。
- 変更がない条件の新旧二重測定は原則不要。例外は回帰リスクが具体的にある箇所。
- 全100ステージの網羅や大量の乱数反復は標準にしない。代表条件＋境界＋既知の問題箇所を優先する。
- 「効果があるか」と「新版として難易度が適切か」を混同しない。
- まず20発／条件を実務上の診断単位として使う。ただし20発で小さな差の統計的有意性やクリア率は主張しない。
- 問題が見つかった条件のみ、追加20発や異なるシードを適用する。正常な条件に機械的な反復を追加しない。

## 2. 事前に明文化する4点

1. **変更対象:** 難易度・ステージ・攻撃種別・敵AIのどこが変わるか。
2. **期待する効果:** 例「静止プレイヤーへの命中が増える」「移動で照準学習を解除できる」。
3. **変えてはいけないこと:** 例「Easyの挙動」「ダメージ倍率」「特殊攻撃の固定パターン」「ステージ100の連戦仕様」。
4. **判定に使う観測値:** 命中数・ダメージ・学習発生・解除回数など。期待方向も試行前に決める。

## 3. Phase A: 効果の検証（変更部分だけ新旧比較）

- **目的:** 変更した処理が効くか、重大な副作用がないか。
- **対象:** 変更開始直後の境界ステージ、典型ステージ、既知の問題ステージから通常は2〜4条件。
- **実行:** 各条件につき旧20発＋新20発。可能な限り同一ステージ・難易度・プレイヤー行動・乱数シード。
- **観測:** 命中数、総与ダメージ、変更機能固有の成立数、内部状態の推移。
- **進行判定:** 期待する方向の変化が少なくとも主要問題条件で見られ、重大な退行がなければ次へ。差が曖昧ならその条件だけシードを追加。期待と逆なら仕様・実装を見直す。
- **重要:** 変更が特定の攻撃種別に影響しない場合は、その種別を対象外または回帰確認のみにする。

## 4. Phase B: 新版の精度・全体バランス検証（新版のみ）

- **目的:** 新版がゲーム全体の各難易度で過度に強い／弱い箇所を生んでいないか。
- **対象選定:** 各難易度の序盤・中盤・終盤、変更開始前後、既存倍率の切替点、ボス／特殊武器、既知の異常ステージ。Normal序盤を省略しない。
- **実行:** 原則1条件20発。Phase Aの新版データは同一条件なら再利用する。
- **比較:** 難易度順序（Easy / Normal / Hard）、ステージ区間の傾向、命中が極端に低い／高いケース、ダメージとの整合性。
- **判定:** 単発の小さな増減で不合格にせず、想定外の逆転、ゼロ命中の集中、過大なダメージ、処理不整合を優先調査。
- **全件調査を実施する条件:** 影響が全ステージに及ぶ、代表条件で広範な異常が出た、またはリリース上の要求がある場合に限る。

## 5. Phase C: 変更固有の動作確認

変更が移動や状態保持を伴うときだけ追加する。

- プレイヤー固定: 学習が成立し効果が継続するか。
- プレイヤー移動: 指定閾値の直下・直上で、**実際の累積移動距離**に応じてリセットされるか。
- 敵の移動: 敵自身が動いても学習が失われず、その時点の地形・位置で弾道が再計算されるか。
- 特殊攻撃: 固定位置攻撃など通常の角度誤差に依存しない処理を壊さないか。
- フェーズ／交代: ステージ100などで、設計で定めた時点に学習をクリアできるか。

**境界値テストは命中20発を繰り返すより、内部の状態遷移を直接確認することを優先する。** 例: 解除閾値50なら累積49で維持、50で解除。70なら69で維持、70で解除。敵移動だけでは解除しない。

## 6. テスト条件の公平性

- 同一条件の新旧比較は、可能な限り同じシード・ステージ・行動・環境を使用する。
- 乱数呼び出し回数を変えて差を歪めない。誤差を無効化しても乱数は従来どおり消費する。
- 敵移動、弾道、地形、武器、特殊攻撃には可能な限り実ゲームのエンジンを使う。
- 診断上20発を継続する場合、プレイヤーHPだけを各射撃後に復元し、**実際のクリア率ではない**と明記する。
- 弾道の近接判定は着弾点のみではなく弾道全体とプレイヤー当たり判定の距離で求める。近接・当たり判定交差と実ダメージを区別する。
- プレイヤー移動は入力値ではなく実移動距離を記録する。地形やキャラクターの歩行補正を考慮する。
- ボスのフェーズ変化など、試験の都合で起こらない進行条件は別テストとする。
- 実行したコミットSHA、設定値、シード、検証用変更の有無を記録する。ゲーム本体への変更と診断コードを区別する。

## 7. 結果の最小出力形式

| 列 | 意味 |
| --- | --- |
| ステージ／難易度 | 比較の単位 |
| 旧・新／移動条件 | 条件の識別（新版のみなら旧列は不要） |
| 命中数／20発 | 実ダメージのある攻撃を命中として計上 |
| 総与ダメージ | 回避可能な命中数と脅威の違いを補足 |
| 機能成立・解除回数 | 学習・リセットなど変更内容に応じて追加 |
| 観察・判断 | 期待方向、異常、未判断、追加試験の要否 |

結果報告は「確認できたこと」「確認できなかったこと」「推奨する変更」「追加検証が必要な条件」だけを短く書く。

## 8. ARCLINE学習機能での具体例（2026-11-04時点の設計）

暫定仕様: Easyは学習なし、Normalは61以降、Hardは21以降。近接30座標。Normalの累積移動リセット50座標、Hard70座標。学習後は角度誤差0%、出力誤差は従来どおり。敵自身の移動では解除せず、毎回現行AIで再照準。

**最小セットの一例（合計300発）**

- Phase A 効果比較120発: Hard21・Normal61・Hard99、それぞれ旧20＋新20。
- Phase B 新版精度140発を追加: Easy5・99、Normal5・60・99、Hard20・61、それぞれ新版20。Phase Aの新版60発を再利用し、新版10条件計200発。
- Phase C 移動40発: Normal99・Hard99、それぞれ左右移動で新版20。加えて、累積50／70の厳密な状態遷移は射撃数を増やさず直接テストする。
- ステージ100の交代時リセットは特殊ケースとして別途、短い回帰確認を行う。

**上記300発は設計事例であって常時固定の予算ではない。** 新しい変更では、影響の大きさ・境界・既知の問題に合わせてさらに減らしてよい。

## 9. 検証開始前のチェックリスト

- [ ] 変更の目的・影響範囲・非変更条件を明文化した
- [ ] 新旧比較は効果検証の必要条件のみに絞った
- [ ] 新版の序盤・中盤・終盤・難易度・境界を代表する条件を選んだ
- [ ] 閾値の厳密な動作は状態遷移テストで確認する
- [ ] シードと計測条件を固定し、差分が再現可能になっている
- [ ] 20発で勝率や統計的有意差を断言しない
- [ ] 異常条件だけ追加試験する停止ルールを決めた
- [ ] ステージ100など特殊仕様の例外を明示した

---
運用ルール: 実装と検証計画は分けて管理する。検証を「網羅するための網羅」にせず、**最小の実行量で変更を判断できる設計**を優先する。
