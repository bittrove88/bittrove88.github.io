## 1. 目的と成功率の取り扱い

ステージ後半で敵の攻撃が外れやすく、プレイヤーがほとんど敗北しない状態を改善する。一方、プレイヤー自身も敵に弾を当てにくいため、敵HPや攻撃回数を増やさず、クリア可能性と緊張感を両立する。

難易度別の**設計目標**は、ステージ81〜100における**1ステージの初回挑戦**のクリア成功率を次のとおりとする。

| 難易度 | 設計目標 |
| --- | ---: |
| Easy | 90% |
| Normal | 80% |
| Hard | 70% |

これらは机上の目標値である。今回の完了条件に統計的な実証を含めない。実測していない数字を達成済みの勝率として報告しない。100ステージ連続無敗の確率とも混同しない。

## 2. 変更対象を限定する

変更は次の3種類に限る。

1. **ステージ別照準誤差倍率**：敵の既存の角度誤差・出力誤差を段階的に縮小する。
2. **難易度別照準誤差倍率**：Easy / Normal / Hardの敵性能差は誤差だけとする。
3. **ステージ別敵ダメージ倍率**：後半のみ最大+10%。難易度モード間の攻撃力差は設けない。

ステージ100は同じ枠組みで調整し、専用の追加システムを作らない。

### 変更しないもの

プレイヤーのHP・射撃性能・弾道物理、通常敵とボスのHP、敵の攻撃回数・攻撃パターン・移動AI、地形、武器、スキル、回復・アイテム、行動回数制限、ボス部位破壊後のダメージ半減、ステージ100の10機連戦・機体交代・固定HP70・各機体必要与ダメージ100などは変更禁止とする。

## 3. ステージ別パラメータ

| ステージ | 敵照準誤差倍率 | 敵ダメージ倍率 |
| --- | ---: | ---: |
| 1〜40 | 1.00 | 1.00 |
| 41〜60 | 0.90 | 1.00 |
| 61〜80 | 0.75 | 1.05 |
| 81〜99 | 0.65 | 1.10 |
| 100 | 0.70 | 1.10 |

敵の**既存の誤差値を基準**とする。通常敵は `errorAngle` / `errorPower`、ボス・中ボスは `enemyProfile` による現行計算を維持する。既存の最適角・最適出力探索も変更しない。

## 4. 難易度別パラメータ

| 難易度 | 敵照準誤差倍率 |
| --- | ---: |
| Easy | 1.40 |
| Normal | 1.00 |
| Hard | 0.65 |

実効角度誤差 = 既存角度誤差 × ステージ倍率 × 難易度倍率

実効出力誤差 = 既存出力誤差 × ステージ倍率 × 難易度倍率

倍率が小さいほど敵の狙いは正確になる。適用は誤差幅に対して行い、算出後の誤差を整数へ丸めない。乱数の消費回数・順番と同一シード再現性を維持する。CPUの通常実行とWeb Worker実行で同一の設定を参照し、モード差は敵の照準誤差以外に生じさせない。

ステージ100の参考値（現行基準：角度±6°、出力±12）：

| 難易度 | 角度誤差 | 出力誤差 |
| --- | ---: | ---: |
| Easy | ±5.88° | ±11.76 |
| Normal | ±4.20° | ±8.40 |
| Hard | ±2.73° | ±5.46 |

`DROP` / `MARK` / `PREPARE` など、固定座標を基準に生成する特殊攻撃は、既存仕様どおり誤差倍率が効かない場合がある。今回その仕組みは変更しない。特殊攻撃についても新たな精度調整は作らない。

## 5. 敵ダメージ倍率の適用範囲

敵側からプレイヤーへの攻撃ダメージのみに、ステージ別倍率を**一度だけ**適用する。敵自身への自傷ダメージ、部位ダメージ、プレイヤーの攻撃、弾道・衝突判定は変更しない。

ボスの部位破壊後に適用される既存のダメージ半減（×0.5）はそのまま保持し、倍率の二重適用を防ぐ。攻撃予測と実際に解決するダメージの一致を維持する。

## 6. プレイヤーの予測射線・難易度UI

現在のEasy / Normal / Hardで異なる予測射線（全軌道 / 半分 / 方向のみ）は廃止し、**全モードで現行Easy相当の全軌道表示**とする。プレイヤーの射撃物理や操作を変更しない。

初回難易度選択、設定画面、説明文（日英）、試射の表示内容を「敵の照準精度が異なる」仕様に更新する。3種類の射線をそれぞれ試さないと開始できない既存の必須条件は廃止・簡略化する。既存セーブの難易度値は尊重し、セーブデータ移行を不要とする。

## 7. 主な実装箇所

- `ARCLINE/game/dist/engine.js`：`cpuPlan()` に実効誤差倍率を適用し、敵ダメージ計算にステージ倍率を反映。
- `ARCLINE/game/dist/game.js` と `ARCLINE/game/dist/cpu-worker.js`：既存の難易度設定をCPUに確実に渡す。処理系間で共通ロジックを使う。
- `ARCLINE/game/dist/aim-guide.js`：全難易度のガイドを同じ全軌道表示にする。
- `ARCLINE/game/ui/difficulty-ui.js`、生成先 `ARCLINE/game/dist/difficulty-ui.js`：表示と初回試射条件を更新。生成手順を守る。
- `ARCLINE/game/dist/index.html` と必要な文言・表示ファイル：難易度の説明を更新する。

変更対象は必要箇所に限定し、関連のないリファクタリング・バランス変更を実施しない。生成物がある場合は元ソースから再生成する。

## 8. 最低限の確認（過剰な検証は禁止）

**① 数値の確認：** ステージ20・60・90・100で、各難易度の実効角度誤差・出力誤差が表・式と一致することを確認する。攻撃力は全難易度で同じステージ倍率になることを確認する。

**② 代表実戦の確認：** ステージ60・90・100をNormalで各1回動作させ、敵攻撃、プレイヤー攻撃、勝敗処理、ステージ100の機体交代が正常であることを確かめる。この3戦の結果を成功率の推定には使わない。

**③ モードと表示の確認：** 3モードの選択・保存・再読込が正常であること、プレイヤーの予測射線が全モードで同一であること、CPUの通常処理とWeb Workerで設定が食い違わないことを確認する。

実行できる既存の短時間回帰テストは活用してよいが、新しい大規模な検証基盤は作らない。

**実施不要：** 1,000戦規模の試行、全100ステージ×全モードの総当たり、複雑な人間プレイヤーモデル、統計的有意差検定、新たなテストフレームワーク。

## 9. 完了条件と報告

- 指定した2種類の照準誤差倍率とステージ別ダメージ倍率が正しく反映されている。
- 難易度モードによる差が敵の照準誤差だけになっている。
- 全モードで全軌道の予測射線を表示できる。
- ステージ100を含め、変更禁止事項と既存ルールが維持されている。
- 上記最低限の確認に重大な不具合がない。

実装担当者は変更ファイル、設定値、簡易確認結果、未検証事項のみを簡潔に報告する。目標クリア率90% / 80% / 70%は**未検証の設計目標**として記載し、達成済みと表現しない。
