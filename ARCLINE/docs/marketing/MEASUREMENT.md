# 検証・計測・公開判断

2026-11-09。ここに書く調査・イベントは候補計画。実施済みの結果、既存GA4の設定、計測実装を示すものではない。

## 1 まず確かめる問い

検証対象は「直感的でテンポがよい」だけではなく、**短いプレイで、自分の一射による面白い出来事が残るか**。

観察時は、最初から「反射が面白いですよね」等の答えを誘導しない。プレイ終了後に、順番に聞く。

1. どんなゲームだと思いましたか。
2. 覚えている出来事はありますか。どこで何が起きましたか。
3. そのとき、何をしようとしていましたか。
4. 続けるなら、次に何を試したいですか。
5. 分かりにくい、待たされた、やめたくなったところはありますか。

発話と操作を対応させ、「自分の判断とのつながり」「結果の理解」「次の試行」「雰囲気や物語への関心」を記録する。面白かったと回答した人数だけでなく、何を楽しんだかを残す。

## 2 少人数の初見観察

最初は5〜8人程度を募集する推奨案。これは統計的な成功判定に必要な人数ではなく、迷いの発見と募集・観察手順の確認のための規模。友人だけ、砲撃熟練者だけに偏らせず、物理・パズルが好きな人と、物語・雰囲気が気になる人を含める。初回の5〜10分を観察し、プロローグが途中の場合は完了まで別に確認する。説明を短くするために物語を切らない。

| 観察項目 | 記録すること | 判断に使う例 |
| --- | --- | --- |
| 狙い | 目標を指せたか、何を変えたか | 操作はできたが何を狙うか不明なら、対象の見せ方を見直す |
| 初回発射 | 入力開始からの経過、迷い、必要だった補助 | 発射できない原因をUI・案内・ロードに分ける |
| 結果 | 弾と作用を追えたか、外れた理由を言えるか | 派手さで結果が隠れるなら、効果を追加する前に読める形へ |
| 面白い出来事 | 本人の言葉と、その場面・操作 | 単なる「楽しい」より具体的な出来事を確認 |
| 次の試行 | 自発的に再調整したか、やりたいことがあるか | 理由なしに同じ射撃を繰り返すなら判断の違いを調べる |
| 物語 | 気になった問い、プロローグ後の理解 | 旅への関心が増えるか。短縮の是非へ自動で結び付けない |
| 再開 | 自分で続きへ戻れたか | 既存ユーザーへの導入再演や開始位置の混乱を発見する |

普段のゲーム嗜好、砲撃経験、端末、観察した版だけを必要な範囲で記録し、個人名や連絡先を公開資料へ載せない。好意的な回答を得た人だけを残さない。初期の人数から市場全体の支持率は出さない。

## 3 ファネルと計測候補

| 段階 | イベントの候補 | 指標・分母の考え方 |
| --- | --- | --- |
| 到達 | `landing_view`、参照元・公開物ID | サイト到達数。SNSの再生数と別に扱う |
| 開始意思 | `play_cta` | CTA率＝クリックしたセッション / 到達セッション。連打を人数に数えない |
| 起動 | `game_ready`、`load_error` | 実際に操作可能になった割合。CTAクリックをプレイ数と置き換えない |
| 導入 | `intro_start`、`first_shot`、`flashback_start` | Bの試撃と本編の発射を `context` で分ける |
| 物語 | `prologue_start`、`prologue_complete` | 完了率＝完了者 / 初回に開始した対象者。中断復帰・既読は区別 |
| 第1面 | `stage_start`、`stage_clear`、`stage_fail` | 第1面開始率と、開始者に対するクリア率を両方見る |
| 続き | `return_session` | 翌日再訪。日本時間の次の暦日に戻った対象者 / 初回に起動し、次日まで観測可能だった対象者 |
| 感想 | 任意の短い質問への回答 | 「具体的な出来事を話した人数 / 回答者」と回答率を併記。全プレイヤーの満足率としない |

「初回発射率」は二種類を混ぜない。Bの先行試撃で初発射した割合と、両群共通の本編第1面で初発射した割合を分ける。Bで早く撃てる構成を作っただけで、面白さや継続が改善したとは判定しない。

最初の30秒の到達を見る場合は、サイト到達から、ゲーム操作可能から、導入開始からのどれかを明示する。ロードや端末の案内を除外した数字だけを全体の体験時間として報告しない。

ブラウザ・埋め込み元・保存領域が異なる場合、同じ人の追跡やセーブを当然に共有できない。識別できる範囲を示し、再訪率に識別不能の対象を混ぜない。指紋採取や不要な個人情報を前提にしない。計測を実装するときに、既存の設定・同意・プライバシーの案内との整合を確認する。

## 4 導入のA/B比較

- A：従来の時系列開始。
- B：先行砲撃→回想→既存プロローグ全編。
- 両方とも同じプロローグ・本編・難易度条件を使う。プロローグあり・なしの比較に戻さない。
- 新規対象を同じ時期に割り付け、同じ人の群を保持する。既存プレイヤーは対象外とし、再開を維持。
- 主に第1面クリアまでの到達と、具体的な面白さの感想を見る。プロローグ完了、初発射、翌日再訪、ロード・保存の問題を合わせて読む。
- 導入を変える比較と、サイトのコピー・動画冒頭を変える比較を同時に重ねない。原因を読み分けられない場合は段階を分ける。

低トラフィックで有意差を断言しない。まず各群の人数・分母・観測期間・欠損・端末・参照元を示す。基準となる実測率を得てから、検出したい差と必要数・期間を決める。数件増えた時点で勝ちとせず、定性観察と併せて次の小さな検証へ進む。

## 5 反応から次の変更を選ぶ

| 観察結果 | 最初に確認すること | 変更の候補 |
| --- | --- | --- |
| 動画を見られない・サイトへ来ない | 接点、サムネイル、投稿先との適合 | 一つの結果が見える冒頭・紹介先を試す |
| サイトに来るが始めない | 遊びの理解、CTA、対応条件 | 実プレイの見せ方・説明の順序・開始導線 |
| クリックするが起動しない | ロード、埋め込み、音声・画面方向 | 配信方式・技術上の入口を直す |
| 撃てるが面白い出来事が残らない | 狙い・結果の因果、判断の単調さ | 目標・作用・次の選択が読めるかを調べる |
| 一射は楽しいがプロローグ後に進まない | 期待のつながり、物語への関心、移行の迷い | 回想の文脈・導線・説明を改善。全編保持を破らない |
| 第1面は遊ぶが戻らない | 次に試したいこと、中断・再開、難しさ | 次の面の判断と再開体験を調べる。翌日率だけで短時間の楽しさを否定しない |
