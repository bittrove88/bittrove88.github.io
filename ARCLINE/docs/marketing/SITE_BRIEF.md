# サイトで担う伝達課題

2026-11-09改訂。[訴求ブリーフ](CONTENT_BRIEF.md)をサイトへ展開するための目的と判断材料。掲載する言葉、構成、情報量はコンテンツライターが決める。

## 誰が、何を判断する場所か

短い紹介を見て興味を持った人、検索や紹介から直接訪れた人が、自分の好みに合うか、実際に遊ぶ価値がありそうかを判断する場所。

中核ターゲットは、自分で作戦を立てて突破し、その成果を強い砲撃の手応えとして味わいたい人。砲撃の見た目から興味を持った人には、その攻撃を選んで使う意味を補う。攻略の工夫から入った人には、判断した結果を味わえる攻撃の魅力を補う。

## 伝えてほしい内容

| 受け手の疑問 | 具体的に分かってほしいこと | 対応する訴求 |
| --- | --- | --- |
| 自分は何をして楽しむのか | 地形・敵・位置・使う技を見て、自分の戦い方を選ぶターン制砲撃ゲーム | M1・M2 |
| 工夫が本当に結果へつながるのか | 遮蔽を開く、別の射点から通す、予告に対して位置を変えるなど、選ぶ理由がある | M1・M2 |
| 攻撃を決めると何が楽しいのか | 技ごとの動きと作用、命中時の反応が、自分で選んだ攻撃の手応えになる | M3 |
| 続けると何が増えるのか | 地形・敵・仲間の違いによって、新しい作戦を試したくなる | M4 |
| なぜこの世界を進めるのか | ガンの便りと旅、仲間との出会いが、攻略の先への関心になる | M5 |
| 自分の環境で始められるか | 対応環境、ターン制の遊び方、開始・保存・再挑戦の実際 | M6 |

伝達の重心は、M1/M2とM3のつながり。機能名や数量の一覧を読んだあと、受け手が自分の作戦を想像できるようにする。100面や10機は、攻略や旅の広がりの根拠として用いる。

## どんなことを感じてほしいか

関心が浅い段階では、自分の判断が活きる遊びへの期待。詳しく知る段階では、砲撃を決める楽しみと、自分ならどう攻略するかの好奇心。始める直前には、自分にも試せそうという安心と、実際に一戦遊びたい前向きさ。

旅・仲間・音楽は、その先も進めたい気持ちを加える。戦闘の理解が曖昧なまま世界設定だけが残る状態、数字の量だけが負担に感じられる状態は見直す。

## ライターに任せること

入口にする関心、見出し、本文、情報の順序、事例の数、物語の語り方、言語ごとの表現。既存のコピーやページ構成を固定の採用条件にしない。

判断の根拠にする商品情報は[商品情報・素材参照](ASSET_PLAN.md)。新導入の実装状態や初期から使える機能を確認し、進行後の楽しみと区別する。利用環境の説明は実際の配信条件へ合わせる。

## レビューで見ること

受け手が「何を考えて遊ぶか」「攻撃が決まると何を味わえるか」「自分は何を試したいか」を説明できるか。始めない場合は、興味の不足、遊びの誤解、利用条件の不明を分ける。[確認観点](MEASUREMENT.md)を使う。
