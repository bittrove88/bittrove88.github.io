# 0.28.1 — iPhone下部UIの幅と安全領域

状態：作業ブランチで修正・検証。本番への追加マージ・配信は未実施。0.28.0（PR125）の不具合修正。

## 原因と修正

- 下部UIの幅が `100% - 24px`、中央位置が画面基準だったため、固定横向きに回転させたiPhoneでノッチ側／ホーム側の左右インセットを無視していた。
- メニューの列が `1fr` で、武器だけの状態でも余った全幅へ伸びていた。440×956相当の縦持ちでは武器ボタン656px、移動ボタン左端18pxで、安全領域59pxへ侵入することを再現。
- 左右の安全領域を別々に差し引いた範囲へ中央寄せし、下部全体の上限を820pxへ制限。武器・スキルの上限は各212pxとし、不在のメニューの幅まで引き伸ばさない。3メニュー時は承認済み844px画面の幅を維持する。
- 横持ちのホームインジケーター領域にも、ボタン下の移動残量・角度・行動回数が収まるよう、下部の余白へ安全領域を加算する。
- 移動・斜角・発射は68×68px、アイコン40px、メニュー高さ36pxを維持。チャージの色・目盛り・数値・高さ26px・操作を維持し、画面全体や戦場を安全領域で縮小しない。
- 正本は `game/styles/battle-ui.css`。キャッシュを0.28.1へ更新し、正式ビルド・紹介サイト画像も同期する。保存schema8/reset2、全100面、物理・AI・武器／スキル性能は変更しない。

## 検証

`iphone-dock-browser` をinput/browserの両スイートへ登録。Chromiumで実際のCSS・固定横向き・回転後のセーフエリア値を使い、440×956・430×932・393×852・375×812、縦持ち正逆・横持ち正逆、左右配置、武器のみ／武器＋スキル／テレポート＋武器／全メニューの128条件を検査する。数字を含む全操作の位置、サイズ上限、チャージ高さ、カメラ倍率、セーブ非干渉を確認する。

iPhoneのインセット値は検査環境で制御した値であり、実機Safariでの確認とは区別する。既存のiPhone回転・チャージ・UI検査、単体37スイート、生成一致も実施する。CIの最終結果は本PRのChecksを参照。
