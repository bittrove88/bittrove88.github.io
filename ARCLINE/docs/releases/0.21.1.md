# ARCLINE 0.21.1 — 100面を10機の総力戦へ

[合意した変更方針](../change-requests/ARCLINE_FINAL_BATTLE_v0.21.1.md)を反映。全10機が固定順に本体へ各10ダメージを与え、最後はガンが決着をつける。達成後は敵の反撃を経て自動交代。各機は通常70％の最大耐久・必殺1発で出撃する。手動交代は出撃順の確認へ切り替え、補助武器・スキルは共通在庫を保持する。

3機ごとに外殻→内殻→核の防護→最後の一射へ移る。各3,000px幅の実地形、機体別の固定出現位置、壁・屋根・崖・中継棚・反射・雲・磁場を組み合わせる。通常カメラは現在の対戦位置に合わせ、全体はマップ表示で確認する。上限36行動。100面だけ既存の敵精度設定4→6。

正本は `stage_blueprints.json` のfinalBattle。`build_campaign.py` が4マップを生成し、`dist/final-team.js` が割当ダメージ・交代・勝利条件を管理する。UI正本は `ui/final-team-ui.js` と `styles/final-team.css`。共有エンジンを使うキャラ／デザイン確認ページにも依存を明示した。幅の拡張は移動・着地・弾の範囲・地形描画・カメラへ反映し、通常幅は従来値を使う。共通の基礎弾道とAI探索は維持する。

表示HPは内部値の20倍。各機の必要量は内部0.5、全体5（表示100）。初回照合で倍率の不一致を修正した。交代で旧機体の反動などが残らないよう除去し、拡張地形の1,000px地点が画面外の地面として延長される描画も修正した。

通常弾だけの3条件、必殺あり1条件とも10機・4戦場を経由して11手で勝利。有限の章在庫は不要。敵の手番を省略せず、通常弾のみの成立を確認した自動探索の記録であり、人の難易度評価ではない。`record_final_stage.py` は今回の4戦だけを更新し、他99面の履歴を保持する。

検証記録は [evidence/final-battle-0211](../../evidence/final-battle-0211/)。他99面のランタイムデータと初期戦闘状態の同一性、共通コードの許可した差分だけの照合、旧セーブ・全員条件・敗北・在庫・実戦を検査。既存の映像・保存テストで用いる模擬勝利は、明示的に全員達成のテスト状態を設定し、本番の勝利条件は緩めない。専用ブラウザで3画面サイズ、日英、出撃順、4マップ見渡し、実戦から保存・ENDINGを確認する。最終CIとPagesはPRに記録する。
