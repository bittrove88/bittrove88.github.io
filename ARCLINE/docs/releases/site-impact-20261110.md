# 紹介サイト再設計 — 読み切れ。撃ち抜け。

2026-11-10。ユーザーの「構成含め全てok」と、メインコピー10案からの「3」を最終合意として、紹介サイトを再設計する。コピーは「読み切れ。撃ち抜け。」に確定。爽快感と必殺技のバリエーションを最初に見せ、好きな技と相棒、作戦、旅、開始へつなぐ。

## 基準と範囲

基準mainは `1badc7c`（0.33.1、PR155の敵位置選び・PR156の発射カメラ・PR158の最終戦検査を保持）。マーケティングの中核ターゲットは、自分の作戦を選び、その成果を砲撃の手応えとして楽しみたい人。[PR150の訴求ブリーフ改訂案](https://github.com/bittrove88/bittrove88.github.io/blob/039b31f8f016da4a3997ba35e047d03f6c421824/ARCLINE/docs/marketing/CONTENT_BRIEF.md)を参照し、今回ユーザーが合意した構成・コピーを優先する。PR150自体は取り込まない。

実装の正本は `index.html` と `site/site.js`・`site/styles.css`。ゲーム本体・バランス・保存・PWA・公開URLは変更しない。サイト改修のためのゲーム版数更新は行わない。起動不良を扱ったPR157の目的も含め、紹介ページが本編モジュールの追加によって停止する依存関係を解消する。

## 構成と動作

1. 「読み切れ。撃ち抜け。」と、連射・分裂・跳弾の映像。ひとり用・ターン制を明記し、ゲーム開始を先に置く。
2. 「好きな一撃で、相棒を選べ。」10機の選択に応じて必殺技・原画・紹介文を切り替える。旅で順に合流することを説明する。
3. 「その地形、突破口に変えろ。」破壊・反射・転移・予告回避を、状況と実際の結果で示す。タブはキーボードでも操作できる。
4. 「次の戦場で、次の自分の作戦を。」現行UIの風景4枚と攻略の変化、20テーマ100面、ガンの便りと物語を一つの旅として紹介。
5. 「狙って、ためて、解き放て。」操作とPC入力、保存・横向き・再挑戦の実際を案内。
6. 「見ていた一撃を、あなたの手で。」既存の本編へつなぐ。全マップ・機体詳細・長尺ムービーは深掘り先へ残す。

紹介ページはrelease-info以外の本編スクリプトを読み込まない。映像・画像・文章を主にし、ゲーム初期化の失敗を紹介ページへ持ち込まない。スクリプト無効・メタデータ失敗・保存領域利用不可・映像取得失敗でも、文章と本編へのリンクを維持する。

映像は消音・インライン。表示中の一つだけを再生し、画面外とタブ非表示では停止する。動きを抑える設定では動画を自動取得・再生せず、画像を使う。明示操作による再生と停止を用意する。原画とゲーム内描画を区別し、終盤の結末は見せない。

## 素材の根拠と再生成

[収録台帳](../../site/showcase-captures.json)に0.33.1のソースハッシュ、映像・画像ハッシュ、弾数・実ダメージ・演出時間と出典を記録する。

- `node game/tools/capture_site_showcase.cjs`：ゲームと同じ物理・描画・モーションによる、セーブ非参照の実演14本と静止画。映像は通常攻略の勝利録画ではなく、実ゲームコードによる用意した実演として表示する。
- 必殺技10本は既存 `attack-review` と同じ実演・演出時間を使い、通常速度でCanvasを収録。追加の爆発・架空の軌道・別試行の勝利は合成しない。
- 地形攻略3本は既存 `site/scenes.js` の操作列・相手の手番を保持。従来のサイトと同じ0.75倍の弾の提示速度を使う。
- 予告回避は60面の固定予告から実際に100移動し、同じ照準・威力の敵攻撃が外れる例。未移動時の被弾と移動後の無被弾を台帳へ記録。移動・敵弾道・命中は実エンジンで計算する。
- 原画は既存の承認済み透過画像から縮小WebPを作り、先読みの転送量を減らす。原画自体は変更しない。
- `node game/tools/capture_site_gameplay.cjs`：現行本編UIの風景4枚と[撮影記録](../../site/gameplay-captures.json)を更新。更新前と画素が同じ写真は差分を作らず、ソースハッシュを更新する。

部分再収録は引数に機体IDまたは攻略IDを指定できる。版が変わった場合は全クリップを収録し、同一版でも関連ソースが変わった際は台帳と一致を確認する。`--art-only` は原画の派生画像だけ、`--webm-only` は既存の収録からWebMを生成する。MP4（H.264）とWebM（VP9）は同じ映像で、ブラウザの対応形式に応じて選ぶ。

### CIで判明したコーデック差

初回と診断用CIでは、CI側ChromiumにH.264の対応がなく、`DEMUXER_ERROR_NO_SUPPORTED_STREAMS` で冒頭動画の再生確認が失敗した。動画の確認をスキップせず、同一映像のVP9 WebMを用意し、ブラウザが対応する形式を選ぶ実装へ修正。ローカルでもH.264非対応の条件でWebMの実デコード・再生と技の切替が成功。420項目のサイト検査と45項目の起動検査が成功した。
