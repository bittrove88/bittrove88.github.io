# 0.28.2：仲間の原画・読み込み同期と通常敵の位置取り

基準main：`861a3e317803c695dfdbbed3991bed4500a22d02`（0.28.1）。今回の直接依頼は、仲間登場画像の欠けを全員分直すこと、画像の準備前に画面・音楽を始めないこと、40面以降の歩行と70面台以降のテレポートを実際に発生させること。作業ブランチで実装・検証中。本番マージ・配信は別工程。

## 原画と表示

全10機を承認原画と比較。旧自動マスクが明るい装甲・アンテナ・羽・砲口・履帯を背景と一緒に除いていた。原画のRGBは変更せず、明示した輪郭の内側3px・外側4pxだけを分類し、さらに内側を必ず保護する。以前から正しく見えていた部品は、指定した範囲の旧αを保護し、修正で再び欠けないようにする。原画と旧αは保持し、新しいαを `design/recruit-art-0282/alpha/` へ追加。正本は `design/ending-roll-preparation/player-masks.json` と `prepare_player_masks.py`、通常ビルドは承認済みαを消費する。

登場用PNGの内容指紋をURLへ付け、古いPNGキャッシュを避ける。全体が収まるcontainを維持し、iPhoneの切り欠きも避ける。原画の右端を暗く隠す旧グラデーションは飛行登場だけ外す。エンドロールも同じ10機の完全な透過素材を使い、原画・敵32体・時刻・音源は維持する。

加入／出会いの再生は、PNGの読み込みとデコードが成功するまで登場パネルを隠し、既存BGM・Web Audioを停止する。待機中は読み込み表示と戻る操作だけを出す。失敗時もCanvasや不完全な登場画面へ進めず、再読み込み／戻るで回復する。未確認の仲間加入状態は消費しない。戻った後に古い非同期結果が届いても、新しい画面へ反映しない。原画準備後に飛行・名前表示・BGMを再開する。スキップボタンは復活させない。

## 通常敵の行動

従来は要件書PR76のみで、戦略的な徒歩・敵テレポートは本番コードに未実装だった。既存の短距離調整は残し、40面以降の通常敵はその場・微移動・60〜140pxの徒歩候補を比較する。実行した歩行の合計は敵1手番140pxまで。候補計算や往復で上限を迂回しない。

71〜79面の通常敵はテレポート最大1回、81〜99面は最大2回。70面・75/80/85/90/95面の固有敵と100面は対象外。現在の実地形から候補を作り、300px以上の離隔、衝突・支持・射線と反撃可能性を検査する。次の自機手番で地形が切り替わっても同じ着地点を保ち、反撃経路が残ることも確認する。固定の着地点表は使わない。

- 有効な歩行先を見送って次の敵手番にも有効候補がある場合は優先する。通常の有効機会も72%で歩行を選べるが、不利な候補や進めない方向へ無理に歩かない。
- テレポートは徒歩より有効な射点がある場合に55〜85%の抽選。戦闘全体の発動率を意味する数値ではない。
- 有効なテレポート機会を連続して2回見送った場合、または射線を作れない敵手番が続いた場合は、次の合法かつ有利な機会で優先する。第3/5/10ターンなどの固定ターントリガーは置かない。
- テレポートは敵1手番を使い、同じ手番の歩行・射撃を行わない。その後の実際の敵2手番は再テレポート不可。ポーズ、試算、敵スキップ、失敗・古い計画で回数や待ち時間を進めない。

判断は `enemy-actions.js` に集約。Workerと非Workerは同じ決定論的な評価器を使う。非Workerは候補間でUIへ処理を戻し、離脱・敵スキップ後の古い計画は破棄する。照準誤差・攻撃武器・ダメージ・敵HPは変更しない。判断の重さや観測用の意図的な空撃ちは、人間の勝率と区別する。

## 保護と検証

地形・100面・プレイヤー操作・在庫・セーブschema8/reset2・既存攻略記録は維持。過去の161入力は歴史的な地形・物理と旧敵行動の回帰検査として保持し、現行の新AIの検証と区別する。別途、全対象通常面で実弾を空撃ちして敵行動を観測し、新しい敵判断を使う6面の完走入力を再生する。ボス・1〜39面は旧計画と比較する。

コードの保護検査は [固定した変更範囲](../../design/recruit-art-0282/CHANGE_SCOPE.json) の3ファイルだけを逆変換し、その他のバイトを従来どおり検査する。新検査では原画10機の画素、待機・失敗・再読込、全機×6サイズ×日英×4表示時刻、Worker一致、非Worker、実際のテレポート手番、歩行上限・回数・待ち時間・着地・反撃を直接確認する。

画面と記録は [確認資料](../../evidence/recruit-enemy-0282/README.md)、最終CI結果は修正PRのChecksを参照。物理端末Safari／Androidは未確認。実装・ローカル検証・CI・マージ・配信・公開URL直接確認を区別する。
