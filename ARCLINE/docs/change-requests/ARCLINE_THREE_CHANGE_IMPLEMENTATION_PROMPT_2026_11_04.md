# ARCLINE｜3変更統合実装 指示プロンプト

## 目的
ARCLINE の現行 `main` を基準として、次の3案件を**ゲームコードへの実装・生成・最小限の検証・実装PR作成**まで完遂してください。これは設計相談ではなく実装作業の依頼です。無関係な機能を変えず、実装担当が判断すべき細部は**既存コード・シミュレーションの結果を比較して実装中に決定**してください。細部の未確定を理由に設計相談へ差し戻さないでください。ただしセーブ破壊や既存契約の撤回を伴う判断はしないでください。

実行前に `ARCLINE/AGENTS.md`、`ARCLINE/docs/UPDATE_RULES.md`、`ARCLINE/game/README.md`、`ARCLINE/game/runtime.json`、現行テスト、関連ソースを確認してください。ブランチ／PR状態とmainの現在SHAを再取得してください。

## 作業ブランチと統合原則
- 最新 `main` から**新規の実装専用ブランチ**を作成し、mainの基準SHAとロールバック可能な差分を確保する。PR #69、PR #72、マップ設計ブランチは、いずれも**mainに未反映の設計資料**として扱う。
- マップブランチはmainと履歴が分岐しているため、**ブランチ全体の機械的マージ／全コミットのcherry-pickは行わない**。1〜50面の承認済み地形JSONと正式な指示書だけを選択的に参照・必要に応じて取り込む。重複する古い案を採用しない。
- 保存と進行、難易度別のデータ分離、固定10機の最終戦、原画、公開URL、他サイトを保護する。旧iOS修正案件は**削除扱いで対象外**。射線表示は**Easy全軌道／Normal半分／Hard方向のみ**で維持する。
- 優先順位：今回のユーザー要求 → 現行コードで確立したゲームと保存の契約 → P3承認済み1〜50面の地形 → PR #69の学習AI → P2の種類・数量・UI・取得方針。競合する場合は「どの案件が変更を許可しているか」を単位ごとに判断する。P3指示書の武器・スキル不変は**地形変更だけを行う場合**の制約であり、P2で明示された武器・スキル・取得物の変更を妨げない。P3で51〜100面の**地形は不変**とするが、P2のカプセルは51〜99面にも適用可能で、PR #69のAIは指定範囲に適用する。

## 実装A：P3 承認済み地形1〜50面
- `STAGES_001_050_APPROVED_FINAL.json` の50件を、現行の正式な地形生成元 `ARCLINE/design/expedition_013/stage_blueprints.json` へ適切に変換し、正規の手順で `runtime_campaign_20x5.json`、ゲーム配布データ、関連生成物へ反映する。
- 幅、分離床、屋根、壁、浮島、敵と自機の出撃支持面、ギミック、個別破壊フラグと学習目標を忠実に反映する。**見た目だけの実装にしない**。天井下面反射（8/35/40）、大型K結晶の描画・物理判定、下降橋40、支持面・転移・独立破壊などを必要な範囲で実装。
- **51〜100面の地形・戦場・ギミックと出撃初期位置は現行mainの値を保持**する。未採用の新マップ51〜100案は取り込まない。100面の4戦場・10機リレー・行動上限・HP・必要ダメージ等は、古い指示文書に残る数字より**現在のゲーム実装の契約**を優先して検証する。

## 実装B：PR #69 敵の近接弾道学習AI
- **Easy 全ステージ：学習なし。Normal 1〜40：なし。Normal 41〜60：学習成立後の角度誤差残存率25%。Normal 61〜100：0%。Hard 1〜20：なし。Hard 21〜100：0%。**
- 敵の通常弾の**実軌跡**がプレイヤーの実当たり判定に30ワールド座標以内まで近づいた際、命中の有無を問わず、その敵の学習を成立させる。学習が成立した射撃は旧精度のまま、**次回の通常射撃から**角度誤差補正を適用。出力誤差・敵与ダメージ倍率を変えない。ボスの特殊攻撃と固定座標攻撃には学習を適用しない。
- 学習成立後、プレイヤーの**累積自力歩行距離**がNormal50／Hard70ワールド座標に達すると学習解除。左右往復は距離を加算、実際に動かなかった分は加算しない。再学習可、戦闘開始・次ステージ・100面の機体交代で初期化。恒久セーブ追加なし。
- 乱数消費・同一シード再現性・通常CPUとWeb Workerの結果一致を確保する。既存の難易度別照準誤差倍率・後半ステージの敵ダメージ倍率・射線UIを変えない。

## 実装C：P2 武器12種・スキル15種・マップ取得46個
- **種類・役割**：基本弾・機体必殺・転移と別に、12種類の補助武器と15種類のスキル（通常12＋レア3）を現行ゲームに統合。指示書の既存9＋新規3武器を基点に、空中爆発系・分裂の実弾道・転がりと地走り・回復などの役割重複を整理する。スキル名・基本効果を尊重する。
- **ダメージ細部は実装時FIX**：`combat.js` の内部1.0＝表示20を基準に、現行のW02等の武器、通常弾、機体必殺、敵HP、弱点、部位、最終100面を確認する。武器別の直撃ダメージ、爆風半径、子弾1発のダメージ、総上限、多段ヒット、回復率、バフ倍率、スキル行動消費・効果ターン、所持上限と1回取得の補充量を**実装・局所シミュレーションの過程で合理的に決定し、数値・根拠・結果を記録**する。PR #72の16/18/24表示などの試算値や34/12配置内訳を**確定値として無断採用しない**。
- **小弾は実用的な単発命中を保証**：二波雨弾の前段／第1波の小弾が全て外れても、後段の**小弾1発が直撃したなら意味のあるダメージ**を与える。扇状・分裂・連射も1子弾の直撃が弱すぎないよう調整し、多段命中の上限を守る。全弾が外れた場合の必中補正や無条件ダメージは不要。ボス弱点・部位保護・リレーを突破しない。
- **46カプセルは必須**：マップ中の武器20・通常スキル20・レアスキル6（完全修復・無敵・全体攻撃を**各2回**）。中ボス撃破報酬は別枠として現行の進行と整合させる。46件の参考候補JSONを起点に、**1〜50面は新承認マップ実装後、51〜99面は現行地形**を使い、実弾道で取得できる面と座標を確定する。100面に新たなマップカプセルは置かない。
- **配置品質**：武器・通常スキルは自機近くへ一律配置せず、敵へ向かう普段の射撃や自然な移動の途中で取りやすい場所に置く。レアは普通より工夫を要してよいが理不尽・不可達は禁止。地形・敵・屋根・橋・ギミックと重複させない。必要なら候補面・候補座標を変更するが46件の分類とレア各2回は変えない。
- **発生タイミングは2パターンだけ**：ステージ開始時／**プレイヤーの5ターン目開始時**。敵の行動や射撃のカウントでずらさない。候補のA34・B12という内訳は未確定。5ターン到達前の勝利時に理不尽な取り逃しが起きない対策と、リプレイ・セーブ復元による重複取得防止を実装・検証する。
- **UI**：武器はオレンジの横長弾薬型、通常スキルはシアンのひし形、レアは金色の二重枠紋章とし、色以外のシルエットでも区別。**各アイコン＋アイテム名称**をマップ上に同時・常時表示。日英ローカライズ・横向きスマホ・カメラ移動・他UIとの重複を確認し、現行の取得操作体系に統合する。
- **在庫・互換性**：章を越える未使用残数の持ち越し、難易度別保存、解放済み機体、古い武器・スキルID・取得済み記録、進行・リトライの引継ぎを安全に実装。古い在庫を無断消去しない。固定スロット数・所持上限・旧クリア報酬や途中取得の例外は実装時に整合を決定。セーブ形式の変更が必要なら既存データからの移行テストを用意する。

## 実装・検証順序
1. 現行mainのゲーム版数・生成ルール・セーブ・ステージ100の契約を検査し、変更前スナップショットと影響範囲を確保する。
2. P3の1〜50地形と必要な物理ギミックを先に実装・生成し、51〜100地形不変を機械的に照合する。
3. PR #69の学習AIを実装し、Normal40→41／60→61、Hard20→21、近接30、歩行49→50／69→70、100面交代、CPU/Workerの一致を検証する。
4. P2の武器・スキルの細部値を現行武器と比較して決定し、1子弾のみ直撃・複数弾の上限・回復・全体攻撃・ボス部位・難易度を小さな実射ケースで検証する。
5. 地形と武器・スキルを実装した状態で46カプセルの最終面・座標・出現をFIX。開始／5ターン目、早期勝利、画面上の形と名称、取得台帳・章跨ぎ・旧セーブの挙動を実測する。
6. 正式編集元と `game/runtime.json` に従って生成する。`npm ci`、`npm test`、`npm run check:generated`、`npm run test:browser`、`npm run build` と変更範囲の重点プレイ試験を実行し、成功・失敗・未実施を明記する。公開・実機未確認を成功と報告しない。100面の特殊戦・開始前導線・難易度別セーブ・ゲーム進行を回帰確認。人間の勝率は実測せず推定達成と報告しない。
7. **実装専用PR**を作り、変更ファイル一覧、3案件の受入条件、P2の最終確定値と根拠、46配置の最終座標と変更点、テスト証拠、未確認事項、51〜100地形非変更の照合を添える。**mainへのマージ・公開デプロイは別途明示承認があるまで行わない。**

## 作業完了の条件
