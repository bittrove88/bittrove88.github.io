## 2. VB-02　再生対象と除外対象

**勝利BGMを開始するのは、通常キャンペーンにおける各章の大ボス撃破・クリア確定時。**

対象ステージ：**10・20・30・40・50・60・70・80・90の9面**。

| タイミング | 使用BGM／動作 |
|---|---|
| 対象面の戦闘中 | 既存のBOSSを継続 |
| 対象面の勝利が確定した直後 | **BOSSを止め、VICTORYを必ず先頭から開始** |
| クリア結果画面 | VICTORYをそのまま継続 |
| 報酬・戦利品確認、仲間加入、編成・案内などの章クリア導線 | 同じVICTORYを継続し、**再スタートしない** |
| 30・60面の幕間映像（通常クリア導線からの上映） | VICTORYを継続。BATTLE_A/Bへ自動変更しない |
| VICTORY曲末へ到達 | **先頭のファンファーレから全曲ループ** |
| 次のステージの実戦が開始した時 | VICTORYを終了し、ステージ規則どおりBATTLE_A/B/CまたはBOSSへ切り替える |
| プレイヤーが次の実戦を始めずタイトル画面へ戻る場合 | VICTORYを終了してTITLEへ戻す |
| ステージ100の最終ボス撃破 | **VICTORYを鳴らさない。** FINAL_BOSS→既存エンディング演出・ENDINGの規則を維持 |
| 通常面・中ボス勝利 | VICTORYを鳴らさず、従来のBGM連続ルールを維持 |
| 通常のストーリー回想や章再生（勝利直後の導線ではない） | VICTORY開始イベントを発生させず、現在の回想専用BGMルールを維持 |
| クリア済み面の練習・模擬戦 | 本編章クリアとしてカウントしないため、勝利BGMの強制開始はしない |

**「毎回0秒から」は章クリアという新しい勝利イベントごと**であり、同じ章クリアの結果画面、加入画面、幕間が開くたびに頭出しすることではない。

## 3. VB-03　イベント判定・多重再生防止

- 画面表示、HUD更新、再描画、結果画面のボタン押下そのものを発火条件にしない。現行の**ゲームエンジンが大ボス勝利を確定した単一のイベント**に紐付ける。
- 勝利条件は単なる「ステージ番号が10の倍数」だけに頼らず、**既存エンカウントの大ボス属性（bossかつmidbossではない）と、stage<100、本編キャンペーン勝利**を確認する。
- 同一勝利イベントについてはBGM再生を**一度だけ発火**。既存の`s.resultHandled`やステージ実行token等と連携して再入・保存リトライ・戦利品処理中の再呼び出しをガードする。
- 発火時は `ArcAudio.request('VICTORY',{restart:true})` 相当を一回行う。**次の章クリアではVICTORYが直前に再生済みであっても必ず0秒へリセット**する。
- 一度開始した後、`ArcExpeditionUi.open`や`playStoryMovie('30'/'60')`等で別のBGMを誤指定しない。幕間・加入から戻ったときも曲を頭出ししない。
- すでに戦闘BGMが止まっている場合や音声再生不可の場合も、勝利処理・報酬・セーブを正常に進める。
- 現行`finishResult()`は、戦利品処理により再入し得る。勝利BGMの開始はこの処理の実際の確定境界に結びつけ、**戦利品の有無で欠落・重複しない**ようにする。演出の遅延を避け、確定勝利が視覚的に示されるタイミングに合わせる。
- 結果画面や加入画面でブラウザを非表示にしたりSDKが停止した場合は、既存の音声状態制御に従い位置保持して復帰する。**一時停止復帰は0秒リスタートではない。**

## 4. VB-04　音楽と他の短い音の関係

- VICTORYは**効果音ではなくBGMとして登録**する。長さ約63秒の既存音源を約5秒に短縮しない。
- **最初のファンファーレを含む全曲リピート**を使用する。BATTLE_A専用のカスタムループ点を流用せず、VICTORYに`loopStart`を設けない。
- 結果画面中もBGMとして連続再生し、仲間加入時も途切れない。仲間加入専用の追加ジングルは今回作成しない。
- 現行`game.js`の結果表示時に鳴る短い`tone()`（勝利側）とVICTORY冒頭が二重に鳴って不自然になる場合、**対象大ボス勝利時だけ旧トーンを抑止**する。通常勝利・敗北の既存トーンまで一括削除しない。
- 同じ大ボスでもゲーム内の練習・回想や結果再表示で、意図しない「勝利BGMの連続頭出し」を起こさない。
- ENDINGは従来どおり1回・非ループ・自動完結、TITLEほか既存曲も以前の規則を維持する。

## 5. VB-05　実装場所・生成元・配布

対象候補（実装前に最新状態を再確認）：

| 役割 | 現行の正本／変更候補 |
|---|---|
| BGM再生状態・track選択 | `game/ui/audio-manager.js` → `game/dist/audio-manager.js` |
| 正式音源メタデータ・生成物 | `design/ending_media.json` → `game/dist/media-data.js`（正規生成） |
| 勝利イベント・結果／次面遷移 | `game/dist/game.js`（関連生成元・生成ルールがあればそれに従う） |
| 章クリアの加入導線 | `game/dist/expedition-ui.js`（原則イベント配線のみ。加入ロジックは変更しない） |
| 30・60幕間の音楽切替 | `game/dist/game.js` の`playStoryMovie`等の条件分岐 |
| ゲーム公開・配布の依存関係 | `game/runtime.json`、`game/tools/build_playables.py`、実際の正規生成・検証スクリプト |
| 新規音源 | `assets/audio/bgm/bgm_victory.m4a` |

`ArcAudio.create`には既に`request(id,{restart})`、snapshot／restore、音声ミュート／ポーズ、loopStartを持たない曲の全曲ループ処理がある。**既存オーディオ管理を全面的に書き換えず、`VICTORY`を新トラックとして追加する。** `VICTORY`はENDINGではないため、通常ループ規則を使用する。二重ロード・旧曲復活など既存の競合防止ロジックを維持する。

`design/ending_media.json`（既存7曲のメタデータ）へ`VICTORY`を追記し、元音源から実測したサイズ・SHA・durationを登録。**ENDINGのタイムライン・裁量・一時停止条件は変更しない。** 生成ファイル`game/dist/media-data.js`は正規ビルドで更新する。トラック数を7固定にしている`game/tools/build_playables.py`の`manifest['bgmTracks']`なども、8曲へ更新するか登録曲数から算出する。

実音源`bgm_victory.m4a`を入手可能になったら正式格納先へ**名前変更だけ**で配置し、元のSHA-256と一致することを確認する。**本書の登録だけでは8曲目のM4AはGit上に追加されない。**

公開版とPlayables ZIPに8曲すべてを正規パスで含める。既存の音源URL解決、ランタイムキャッシュ識別子、PWA、YouTube SDKの音声許可・停止仕様を維持する。セーブスキーマ・リセット番号・100ステージデータは変更しない。音源が未配置の途中段階はゲーム本体を壊さず、指定曲がないことを開発者向けに報告する。

### 最終確定

**②の勝利曲を1曲のBGMとして採用。9つの大ボス章クリアごとに、冒頭ファンファーレから必ず再スタート。結果画面・仲間加入・30/60面幕間を経て、次のステージが始まるまで同じ曲を継続。曲が終わったら冒頭を含めて全曲ループ。100面の最終ボスだけは既存エンディングへ直結する。**
