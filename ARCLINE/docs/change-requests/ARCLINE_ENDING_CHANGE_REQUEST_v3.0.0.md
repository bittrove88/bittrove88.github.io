現行エンディングはストーリーの内容を維持し、上映を約1.1〜1.2倍へ調整する。その後の自キャラ紹介を、静止画像の突然の切り替えから、動きのあるエンドロールへ変更する。

## 11. ER-10　時刻・停止・読み込み・失敗

- 全体時刻はENDINGの実メディア時刻を優先する。フレーム数・画面遷移回数・個別setTimeoutの足し合わせで進行を決めない。
- 音源が欠落・拒否・停止した場合は既存の検証済み尺による単調時計の代替を維持し、永久にロゴや待機表示へ留めない。代替時計でも同じ順序と区間境界を使う。
- **横向きのときだけ再生**。縦向きでは回転案内を出し、映像・字幕・ロール移動・音楽・代替時計を停止。横向きへ戻ったら同じ時刻・同じ個体・同じセッションで再開する。
- SDK停止、document非表示、回転は独立した停止原因として管理。回転復帰でSDK停止を解除しない。非表示時間をまとめて加算して飛ばさない。
- 画像は現在と次の少数の組を先読みし、必要なものを事前decodeする。原画42枚・全音源の一括展開や巨大Canvas常駐を避ける。
- ロード遅延でBGMを頭出し・ロールを巻き戻し・区間を延長しない。画像欠落時は名前・背景等で安全に進行し、ゲーム描画へフォールバックしない。正常条件で指定個体が欠落した状態は検収合格にしない。
- reduced motionでは大きなスクロール・揺れを抑えた短いフェード等へ置換してよい。同じ順序・時間・全個体の識別・終了を維持する。

## 12. ER-11　入力・保存・本編の終了条件

既存のENDINGの手動操作禁止を維持する。スキップ・次へ・一時停止のボタンを出さず、クリック・Enter・Space・ArrowRight・Escape・キー長押し・画面を閉じる処理等から途中送りや意図しない終了を起こさない。OS・タブ終了やブラウザ履歴による移動を強制的に封じる仕様にはしない。これらで中断しても既存のクリア進行を失わせない。

100面の本編クリアは保存成功を確認してからENDINGへ進む。終了通知、journal／moviesSeen更新、保留加入、保留映像、報酬処理との順序を維持する。保存リトライや画面再表示で曲が二重に始まらないこと。100面の練習クリアを新規本編クリアとして扱わない。

章の回想では攻略進行、装備、解放、持ち物、加入途中の状態を変更しない。終了後は元のストーリーモードへ戻り、従来のBGM復元規則を維持する。セーブキー、schema、resetVersion、100面、戦闘性能、機体性能、公開URLを変更しない。

## 13. ER-12　本編と一時確認ページ

本編と `ending-preview/` は同じタイムライン定義、出演者台帳、元画像、名前、速度、曲尺を参照する。確認ページだけ新演出にして本編を旧構成のまま残さない。重複した固定時間・独立した出演者リストを増やさない。

一時確認ページはゲーム本体・セーブのロードを必要とせず、攻略記録のlocalStorage／SDK読み書きを一切行わない。「横向きで再生ボタンを押すだけ」の導線を維持し、正常起動時にロゴのみで止まらない。終了後に再生ボタンへ戻し、次回は0秒から始める。音声開始は利用者の操作に結び付ける。

既存の `game/dist/?preview=ending` の互換導線を残す場合も同じ新演出へ接続し、保存しない条件を維持する。読込失敗は目に見えるエラー表示と再試行手段を用意し、無言のロゴ画面へ閉じ込めない。
