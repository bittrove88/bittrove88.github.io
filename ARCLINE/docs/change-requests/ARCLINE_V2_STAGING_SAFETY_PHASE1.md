# ARCLINE v2 STG安全性 第1段階の変更指示書

- 変更ID：ARV2-BASE-001
- 状態：実装準備PoC。本番未反映
- 変更禁止：ゲーム本体、公開設定、本番セーブ、既存公開URL、他サイト

## 目的
将来の同一ドメイン別パス /ARCLINE-staging/ で、本番公開前のプレイ確認を行う。共通ゲーム本体を二重実装せず、STGは開始ステージの数値入力（1〜100）とゲーム開始だけを追加する。入力NはN面から開始し、1〜N面のステージ選択を可能にする。難易度・機体・装備は通常のゲームUIで操作する。STGの進行状態は一時メモリのみ。

## 第1段階の実装範囲
1. ステージング更新候補のPagesサイト全体と、現在公開中の承認済みPages成果物をファイルハッシュで比較する。
2. /ARCLINE-staging/ 以外のパスが変更・削除・追加されれば、公開を禁止する。STG本編入口がなければ禁止する。シンボリックリンクを禁止する。
3. 変更の単体テストを読み取り専用のActionsで実施する。Pages公開権限は持たせない。
4. 本番ゲームと現在のPages公開方式は変更しない。

## 次の工程で必要な検証
- 同一オリジンの保存領域：本番の既存セーブ・設定をSTGが読み書き・削除しないことを、ブラウザのアクセス監視と変更前後の保存値照合で検証する。
- STG N=1/50/100、難易度変更、ステージ遷移、加入・章持ち物・最終戦の初期状態を検証する。
- 共通ゲーム本体、資産、公開URL、PWA、セーブ、全100面、他サイトへの影響を検証する。
- Pages公開方式変更は、権限・並行公開・完全スナップショット・復旧をPoCで検証後に別PRで実施する。
- 変更ID・目的・ファイル差分・依存関係・検証・承認をPRで管理し、承認済み変更だけのリリース候補を再検証して本番へ昇格する。
- 本番反映前の全ゲートPASSと明示的な承認を必須とする。

## 完了条件
安全チェックの単体テストが合格しても、本番全機能の無不具合や同一オリジンの物理的隔離は実証できない。STG公開・本番昇格・ゲーム本体変更は本書のPoCの範囲外。
