## 1. 指示と適用境界

**目的**：全100面の難易度曲線を維持しつつ、ボス10面すべてを直前の通常面より明確に難しくし、特に50・80・90面を節目の難関へ変更する。40〜99面では平坦で同一高度からの撃ち合いが続く問題を改善する。大ボス以外の差し替えは上記の通常20面に限定。中ボスは変更しない。

**不変条件**：既存ボスID/部位/攻撃パターン、物理・射角・弾道・敵攻撃力・難易度選択（ガイドの表示量のみ）、機体と解放順、章在庫、物語と演出、BGM、セーブschema8/resetVersion2、公開URL/PWA、140px/ターン自力歩行上限を維持する。新しいギミック種類や不可視のランダム現象を導入しない。通常弾のみでもすべての面で成立経路を残す。既存弾種・必殺・有限在庫を必須にしない。

**100面の確定済み契約を最優先**：10機固定順（ハナ→コロ→バン／ソラ→リコ→ヒバリ／モグ→リン→ユイ／ガン）、本体へ各機表示10ダメージ、反撃後に生存して自動交代、各機通常耐久70％・必殺1発、36行動、3/6/9機達成時の戦場切替、各戦場3,000px、敵プロファイル6、最終ガン、物語/エンディング継続を不変とする。戦場だけ変更。

## 2. データ仕様と座標

- JSON各要素は現行 `stage_blueprints.json` と同一の `stage`, `name`, `nameEn`, `goal`, `goalEn`, `floor`, `parts`, `features`, `recommended`, `spawn`, `route` 等を持つ。差し替え後の**全体100件**を保持し、対象30件だけをstage番号で置換すること。レコード順と他70面は不変。
- `floor`：座標 `[x,h]`、一般面はx0〜100（1単位10px）。高さhは上方向へ増加。必要な空隙は `floorSegments` で切る（43/61/86面）。`parts` は `wall` / `island` / `roof`、`features` は既存 W/B/C/K/U/F/V/M/T 等を使う。洞窟は地面・屋根・壁の既存衝突ポリゴンを組み合わせて表現し、新しい洞窟物理を追加しない。
- `spawn` は基本的に[xP,xE]のみ。縦座標は現行 `build_campaign.py` の床補間で決定される。30/90面の `enemyAirHeight:10` は維持。100面だけ従来どおり専用 `finalBattle.maps[*].spawns` / `bossSpawn` を持つ。
- 床の傾斜・崖・衝突は既存走行ルール（登坂限界など）で実機生成後に確認する。浮島への歩行到達を前提とせず、既存の転移・弾道で到達性を検証する。破壊可能な壁と指定した屋根のみ破壊可能とする。
- JSONは**ブロックアウト初期値**であり、敵AI・弾道・着弾・転移・クリアの実測済み座標ではない。実際に試行し、必要な座標だけ調整する。ボス/ステージ名は維持。

## 3. 難易度曲線の固定

| 範囲 | 位置づけ | 戦術の増分 |
|---|---|---|
| 1–10 | 入門 | 射角と水面、10面は単純な高度差で一段難しく |
| 11–30 | 初級 | 単独ギミックと射点、30面は浮島と空中敵 |
| 31–49 | 中級 | 反射・屋根・高低差。40面は峡谷と反射、41–49面は次の上級へ橋渡し |
| 50–79 | 上級 | 高度・破壊・2ギミックの組み合わせ、50面は初の本格的な多層坑道 |
| 80–89 | 超上級 | 端子・磁場・浮島の経路比較、80面は既知技術の統合 |
| 90–100 | 最終試練 | 雲/風/高低差の総合、90面は三層空母、100面は既存10機総力戦の強化 |

大ボスの強化はHPやAIの不公平な加算ではなく、(1)事前の地形把握、(2)複数射点の比較、(3)開放する遮蔽の選択、(4)射撃後の反撃への備えで作る。面をまたぐ装備・経験前提で詰ませない。10/20/30の認知負荷は低く保ち、50/80/90を重点にする。

## 6. 位置差と地形バリエーションの検収

変更対象の通常20面は、すべて初期P/Eの床高度差を6以上とするブロックアウト（本設計JSONの静的計算による、弾道テストではない）。洞窟・屋根型、浮島・空中型、高低差・崖型、特殊複合型が連続して同じ見た目にならないよう、アトラスでシルエット比較する。

40〜99面の現行観測は「地面高低差3以下24/60」「P/E初期高度差1未満18/60」。このうち差し替え通常20面で小高低差16面・同高度15面以上を重点解消する。大ボス地形変更も加え、実装後の再集計で**地面高低差3以下は8/60以下、同高度は3/60以下**を採用目標とする。浮島・屋根の上を歩けることは床高度差だけでは表現されないので、形状・安全な着地点・ルートの実質差も別に検収する。

### ボスごとの難度受入

- 全10ボス：少なくとも2つの再現可能な通常弾攻略経路（基本/代替）。直前通常面より、位置・遮蔽・ギミックの判断を増やす。初見失敗の原因が画面上で理解できる。
- 50：縦坑＋浮島＋天井開放で明確な複数射点を成立。ドリル/排気部が同じ射点で一方的に撃てない戦術を用意（ただし全通常弾で勝てる）。
- 80：極性操作と高度変更が**別々の有効ルート**となる。端子を押すことだけを強制しない。
- 90：下層風陰・中段浮島・上層主甲板の少なくとも2経路が安全に成立。既存敵空中高度と雲・風で破綻しない。
- 100：10機固定順の全戦場で、敵の手番を含めた全員生存クリアが成立。通常弾のみの実戦3乱数条件＋必殺あり1条件、36行動上限、各機10表示ダメージ条件、保存→ENDINGを確認。

## 7. 実装時の作業順・検証・完了条件

1. ベースと競合照合：`stage_blueprints.json` 最新との差分を比較し、30件以外を保持。既存の `floorSegments` は本JSONに指定がない変更面では除去（旧形状の残留を防ぐ）。
2. 優先順：50→80→90を実装・実戦計測。その結果に合わせて通常20面、その他7ボス（10/20/30/40/60/70/100）を調整。現行 `0.21.2` 保存/移動仕様を守る。
3. 生成順：`game/tools/build_campaign.py` と正式 `npm run build`、`npm run check:generated` を用い、`runtime_campaign_20x5.json`、`stage_design.json`、`STAGES_JA.md`、`arcline_100_maps_atlas.html`、生成 `levels.js` 等が一致することを確認。
4. 静的検証：x昇順・地形端点・分割面・障害物の重なり・坂の角度・床接地・出現地点・PWA横画面・カメラ表示・140px制限を確認。空隙の唯一の解が有限武器に依存する状態は禁止。
5. 実エンジン攻略検証：変更30面を通常弾のみ3乱数、推奨機体1条件、敵反撃込みで検査。通常20面は既存行動上限16または20、ボスは24/28、100面は36を維持。旧攻略ログは新設計に流用せず新証拠を記録。
6. 回帰：未変更70面の設計レコードとランタイム初期状態を変更前後で照合。解放・在庫・保存・読み直し・ステージ選択後の本編継続・音楽・エンディングを検証。CI/Pages/物理iOS・Android/人の難易度は別々に報告。
7. 人手の試遊：50/80/90/100の各面で「狙いどころが視認できるか」「初回に攻略方針を理解できるか」「理不尽な遮蔽・見えない風がないか」「リトライで改善できるか」を確認。自動探索のPASSだけを体感難度と扱わない。
